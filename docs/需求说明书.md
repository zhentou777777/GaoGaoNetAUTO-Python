## 二、项目背景

### 2.1 场景

学校使用**云高（广州云糕科技）统一认证**的校园网。典型形态：

- 电脑接入校园网后，需访问认证网关 `hgs.auth.yungao-tech.com:1110` 完成认证才能上网。
- 认证凭据是一枚 `Authorization: Bearer <Token>`，**服务端只认这枚 Token**。
- 网页登录流程是：打开认证页 → 拿到一次性 `code` → 带 Token 请求 `/api/network/auth?str=<code>` → 授权落到某台设备。

### 2.2 痛点

| 编号 | 痛点 | 具体表现 |
|---|---|---|
| P1 | **扫码很麻烦** | 每次重连都要掏手机打开 APP 扫一次码 |
| P2 | **扫码只有一次有效** | 扫码换来的 Token 是**单次使用**的，断了还得再扫 |
| P3 | **每次开机都要手动认证** | 开机后电脑不能自动联网 |
| P4 | **断了不会自动恢复** | 网络抖动/换宿舍后必须人工介入 |
| P5 | **单设备套餐互踢** | 电脑上认证会把手机顶下线；手机重连又把电脑顶下线，形成"抢登录"死循环 |
| P6 | **想两台同时用做不到** | 套餐只允许 1 台设备在线，电脑与手机无法共存 |
| P7 | **Token 会失效** | 在 APP 内退出账号、或发生设备登录后，Token 立刻失效，工具变砖 |
| P8 | **分发受阻** | 未签名的 exe 在第二台电脑上被杀毒软件拦截（下载 + 运行双拦） |

### 2.3 核心技术洞察

云高把「**身份**」和「**这次授权给哪台设备**」拆成了两件事：

- 身份 = 请求头里的 `Bearer Token`（服务端唯一认定）
- 授权载体 = 一次性的 `code` / `str`（网页流程里传参用）

因此 `GET /api/network/auth?ip=<设备IP>` 配合一枚有效 Token 就能**跳过整个扫码流程**直接认证。这是「免手机」的全部技术依据。

而 Token 的续命方式又被逆向出来了：`POST https://user.v4.yungao-tech.com/api/login`，body 为 `{"mobile","password"}`，直接换回 Token。**这让"完全自愈"成为可能**——断网后不需要任何人工介入。

## 四、功能需求

### 4.1 认证模块（`auth.py`）

| 编号 | 功能 | 输入 | 输出 | 异常路径 |
|---|---|---|---|---|
| F-1 | 本机出口 IP 探测 | 认证网关 host/port | 本机出口 IP 字符串 | UDP connect 失败 → `_fallback_ip()` 遍历网卡 |
| F-2 | 网关/默认路由探测 | 系统信息 | 默认网关 | `netprobe_win`（ctypes 调 `iphlpapi`）失败 → 返回空；优先取承载出口 IP 的那张网卡的网关 |
| F-3 | NAT 模式判定 | 出口 IP | 是否处于 NAT 之后 | **保守启发式**：私有出口 IP + 排除 `10.135.` 校园网段 + 默认网关为私有地址；**判不出就返回 False**（宁可不提示，也不误判） |
| F-3b | **已在线权威判定** | 出口 IP + Token | 服务端在线列表里是否已有本机出口 IP | 这是「共享模式」的唯一依据——查服务端列表，而非本地猜测 |
| F-4 | MAC 地址获取 | 系统信息 | `xx:xx:xx:xx:xx:xx` | `netprobe_win.mac_for_ip()` 失败 → `_mac_fallback()` 取活动网卡物理地址，再退到 `uuid.getnode()` |
| F-5 | 免扫码认证 | IP + Token | `AuthResult` | 401/403/410 → TOKEN_INVALID；409 → DEVICE_LIMIT；返回 HTML → NOT_AUTH；重定向到外部站点 → NOT_AUTH |
| F-6 | 扫码末跳认证 | `str` + Token | `AuthResult` | 同 F-5 |
| F-7 | 下线某设备 | IP + Token | `AuthResult` | 失败仅记日志，不中断主流程 |
| F-8 | 查询在线设备列表 | Token | `[{ip, type}]` | 解析失败 → 返回空列表（不阻断认证） |
| F-9 | 查询单 IP 在线状态 | IP + Token | bool | 解析失败 → False |
| F-10 | Token 健康检查 | IP + Token | `AuthResult`（不改变在线状态） | 同 F-5 |
| F-11 | 设备列表人话化 | 在线设备 + 本机 IP | `手机 WIFI 10.1.2.3 \| 电脑有线 10.1.2.4（本机）` | 空列表 → "当前无在线设备" |
| F-12 | 服务端下发新 Token 提取 | 响应体/响应头 | 新 Token | 未找到 → None（退回旧 Token） |
| F-13 | **传输安全闸门** | host / scheme / port | 是否允许发送带 Token 的请求 | 非白名单主机 → **在发出请求前拦下**并返回原因；白名单在 `config.ALLOWED_HOSTS` / `ALLOWED_SCHEMES` |
| F-14 | **HTTP 风险提示** | 当前 scheme | 提示文案 | `scheme == "http"` → 明确提示 Token 会明文过内网；https → 无提示 |

### 4.2 认证链（`login_chain`，四级 + 共享前置）

| 顺序 | 阶段 | 条件 | 说明 |
|---|---|---|---|
| 0 | **共享模式** | 本机出口 IP 在服务端在线列表中 | 直接判成功，**绝不 logout**，这是"不挤手机"的根因 |
| 1 | 直连 | — | `auth?ip=` |
| 2 | 清理陈旧会话 | 直连失败 | 先 `logout` 本机 IP，再 `auth?ip=` |
| 3 | **自动抢占** | 仅 `takeover=True` | 逐个 logout 其它在线设备，再认证本机 |
| 4 | 顶替指定手机 IP | `kick_phone` 且已填 `phone_ip` | logout 手机 IP 后认证 |
| 5 | 明确归因 | 全部失败 | 按 TOKEN_INVALID / DEVICE_LIMIT / NOT_AUTH 分别给出可操作提示 |

> **`takeover` 语义（关键设计）**：`takeover=True` 仅用于**用户主动点击**（「立即认证」/「抢占上线」）；自动重连一律传 `takeover=False`。否则守护线程会与手机 APP 互踢，形成无限循环。

### 4.3 自愈模块（`login_chain_self_heal`）

| 层级 | 触发条件 | 动作 | 依赖 |
|---|---|---|---|
| **L0** | 认证失败且判定 TOKEN_INVALID，且已配置账号密码 | `POST /api/login` 换新 Token → 重跑认证链 | `acclogin.py` |
| **L1** | 认证过程中服务端在响应体/响应头下发了新 Token | 提取并自动续存到配置（`token_prev` 备份旧值） | `auth.py` `_extract_new_token` |
| **L1b** | 当前 Token 认证失败（判定 TOKEN_INVALID） | **回退重试**一次上一版 Token（`token_prev`）；成功则继续用旧值 | `config.get_token_prev()` |
| **L2** | Token 确实拿不到，但用户在场 | 降级到扫码登录（本地渲染二维码，无需 APP 页面） | `qrflow.py` |
| **L3** | 以上全失败 | 提示重新抓包（设置面板「怎么获取？」有图文步骤） | — |

### 4.4 守护模块（`netguard.py`）

| 功能 | 细节 |
|---|---|
| 连通性探测 | **带预期内容的 HTTPS 探测**：依次请求 `connectivitycheck.gstatic.com/generate_204`（期望 `204`）、`msftconnecttest.com/connecttest.txt`（期望 `Microsoft Connect Test`）、`captive.apple.com/hotspot-detect.html`（期望 `Success`）；**HTTP 200 且响应体含特征串**才算在线 |
| 门户劫持识别 | 301/302/303/307/308 重定向（captive portal）一律**不算在线**，继续试下一个目标 |
| 探测周期 | 20s（`interval`） |
| 启动延迟 | 守护线程启动后先 `sleep(3)`，避免与开机自启抢网络 |
| 断网判定 | 连续 **2 次** 探测失败才上报，避免瞬时抖动误触发 |
| 出口 IP 漂移 | 检测到本机**出口 IP** 变化即上报 `ip_changed`（校园网重分配地址后旧授权失效）。以出口 IP 为准，而非网卡 IP —— 走热点时网卡 IP 不变但出口已换 |
| 重连退避 | 15s → 30s → 60s → 120s 封顶（`retry_base=15, retry_max=120`） |
| 重连不抢占 | 重连流程只做**非抢占式**认证，避免与手机互踢 |

### 4.5 扫码模块（`qrflow.py`）

| 功能 | 细节 |
|---|---|
| 会话建立 | `GET /web/network/code?...&clientip=&clientmac=&wlanacname=` → 解析页面 |
| 二维码本地渲染 | XOR 解混淆 `encoded[]` + 每会话随机 `key` → 解出载荷 → `segno` 本地生成 PNG，**不依赖 APP 页面** |
| 载荷等价性 | 解码结果与 cookie `str` 完全一致 |
| 过期判定 | 用**本地计时**：`_created_at + SESSION_TTL_MINUTES*60`（10 分钟）。**不能**用「UUID 变了 = 过期」判断——服务端每次请求 `/web/network/code` 都会下发新 `str` |
| 会话固定 | `_session_cookie` 固定保存原始 UUID，防止轮询时重拉页面覆盖 cookie |
| 轮询 | 定时 `poll()` 拉授权状态 |

### 4.6 账号密码模块（`acclogin.py`）

| 功能 | 细节 |
|---|---|
| 接口 | `POST https://user.v4.yungao-tech.com/api/login`，body `{"mobile","password"}` |
| 必需字段 | 仅 `mobile` + `password` 两个；换别的键名 → 400「参数不能为空」 |
| Token 提取 | `_pick_token()` 递归查找 `token/accessToken/access_token/idToken/id_token/jwt/authorization/userToken/user_token/authToken`，再兜底匹配 JWT 形态（长度 > 40 且含 2 个 `.`） |
| 错误分类 | 400 参数不匹配 / 408 手机号不合法 / 401 账号不存在 / 401 密码错误 / 需验证码 / 需短信 |
| 脱敏 | `mask_mobile()` → `131****2536`，日志只显示脱敏形式 |
| 明文口令 | 口令**不落盘明文**，`account_password` 与 Token 同方案加密 |

### 4.7 配置模块（`config.py`）

| 功能 | 细节 |
|---|---|
| 存储位置 | **改造后**统一 `%LOCALAPPDATA%\GaoGaoNetAUTO\config.json`（可用环境变量 `GAOGAO_DATA_DIR` 覆盖）；目录创建时收紧 ACL（仅当前用户 + SYSTEM + Administrators 可写） |
| 加密方案 | **Windows DPAPI**（`CryptProtectData`，系统级、用户绑定、随机 nonce、自带完整性校验）→ `dpapi:<base64>`；DPAPI 不可用时降级为 PBKDF2-HMAC-SHA256(100k) + HMAC-SHA256 认证加密 → `v3x:<base64>` |
| 密钥种子 | DPAPI 由系统 LSA 托管，程序不读取任何机器指纹；降级方案的主密钥存 sidecar `vault.key`（0600） |
| 向后兼容 | `decrypt_token()` 兼容手工填写的**明文** Token；旧 `v1:` / `v2:` 混淆密文仍可解密，读到后立即重写为 DPAPI |
| 自动备份 | 每次 `save()` 后写 `config.json.bak`（保留 1 份）；主文件损坏时自动回退读备份 |
| 账号密码 | `account_mobile` 与 `account_password` **均加密存储**（同走 DPAPI），手机号仅在日志/界面以 `138****8000` 形式出现 |
| 清除凭据 | `Config.clear_credentials()` 抹掉 Token / 上一版 Token / 手机号 / 密码，覆写删除备份文件与临时二维码；界面对应「清除已保存凭据」按钮（二次确认） |

| **安全性** | 凭据文件不被同机其他账号读取 | 数据目录 ACL 收紧（仅当前用户 / SYSTEM / Administrators），并对关键文件覆写删除 |
| **安全性** | Token 不会被误发到非网关主机 | 网关主机/协议/端口**白名单闸门**（保存时 + 每次请求前双重校验） |
| **安全性** | 日志不泄漏凭据 | 落盘日志统一脱敏（Authorization 头、`token`/`password` 字段、11 位手机号、≥24 位长串），并自动轮转 |
| **安全性** | 不做设备唯一标识采集 | 改造后取消 MachineGuid 读取（保留双密钥兼容以不丢老配置） |
| **兼容性** | Win10 / Win11 x64 | tkinter + requests，零额外运行时依赖 |
| **兼容性** | 三种分发形态可用 | onedir zip / onefile exe / 源码绿色包 |
| **可维护性** | 模块职责单一 | 认证 `auth` / 配置 `config` / 守护 `netguard` / 扫码 `qrflow` / 账号 `acclogin` / 业务 `core` / 界面 `webui`+`tkui` 分离 |
| **可维护性** | 不依赖第三方 Markdown 库 | `docs/build_html.py` 纯标准库实现 |
| **可交付性** | 不被杀毒软件拦截 | 改造后：onedir + 无 UPX + 版本资源 + 自签名 + 无子进程 + 无注册表 Run |
| **可诊断性** | 出问题能自证 | 自愈状态条、在线设备摘要、实时日志、`tools/login_check.py` / `tools/tokenlab.py` 诊断脚本 |

## 七、接口需求

### 7.1 核心接口

| # | 方法 | 路径 | 关键参数 | 用途 |
|---|---|---|---|---|
| 1 | GET | `/web/network/code` | `clientip` `clientmac` `wlanacname` `paip` `vlan` | 取会话与二维码载荷 |
| 2 | GET | `/api/network/auth` | `ip` | **免扫码认证主路径** |
| 3 | GET | `/api/network/auth` | `str` | 扫码末跳 |
| 4 | GET | `/api/network/logout` | `token` `ip` | 下线某设备 / 归还名额 |
| 5 | GET | `/api/network/online` | — | 在线设备列表 `[{ip, type}]` |
| 6 | GET | `/api/network/onestatus` | `ip` | 查某 IP 是否在线 |
| 7 | POST | `https://user.v4.yungao-tech.com/api/login` | body `{"mobile","password"}` | 账号密码换 Token |

所有网关请求头带 `Authorization: Bearer <Token>`；`User-Agent` 模拟浏览器。

### 7.2 `type` 字段语义（逆向自 APP）

| 值 | 含义 |
|---|---|
| 1 | 手机 WIFI 使用中 |
| 2 | 电脑有线使用中 |
| 3 | 电脑 WIFI 使用中 |

### 7.3 错误码语义

| 码 / 特征 | 分类 | 含义 |
|---|---|---|
| 200 / `code=0` / `success=true` | OK | 成功 |
| 401 / 403 | TOKEN_INVALID | 服务端拒绝该 Token |
| **410** | TOKEN_INVALID | 登录状态已失效（Token 过期 / 未认证 / 在别处登录） |
| **409** | DEVICE_LIMIT | 套餐只支持单设备，已有设备在线 |
| 400 | 未知 | 参数不能为空 / 参数不匹配 |
| 408 | — | 手机号不合法（账号密码登录） |
| 401（账号接口） | — | 账号不存在 或 密码错误 |
| 返回 HTML | NOT_AUTH | 认证接口返回网页 → 未连校园网或被门户拦截 |
| 被重定向 | NOT_AUTH | 请求被打到别的站点 → 同上 |
| 700 / 701 | — | APP 内提示 / 单设备弹窗文案 |

### 7.4 服务端实测行为（重要）

| 场景 | 结果 |
|---|---|
| 无设备在线 → 认证 A | **200** 成功 |
| A 在线 → 认证 B | **409**（套餐单设备） |
| A 在线 → 再次认证 A | **409**（幂等拒绝，已在线的 IP 也不放行） |
| 下线 A → 再认证 A | **200** 成功 |
| `onestatus` 判定 | 按 IP 段：`10.135.130.x` 整段在线，`1.2.3.4` 不在线 |
| 抢占可行性 | `logout 手机IP` → 200，`auth 电脑IP` → 200，**接管无需手填手机 IP** |

## 八、约束与边界

| 编号 | 约束 | 影响 |
|---|---|---|
| C1 | **单设备套餐** | 电脑与手机默认互斥；共享模式与抢占是两条出路 |
| C2 | 网关是**明文 HTTP**（端口 1110） | 协议本身决定，不能改；Defender 网络保护可能告警 |
| C3 | 网关 host/port **随校而异** | 必须做成配置项，不能写死 |
| C4 | Token **绑定机器指纹加密** | 拷贝 `config.json` 到另一台机器解不出 Token → 多机部署应统一用账号密码 |
| C5 | 扫码会话 **10 分钟**过期 | 过期后需重新生成二维码 |
| C6 | 账号密码登录接口**未确认需要验证码/短信** | 若云高侧开启验证，L0 自愈会降级失败，需回退扫码 |
| C7 | `pystray`/`Pillow` **可选** | 缺失时托盘不生效，界面需能正常降级 |
| C8 | 未签名 exe **会被 Defender 拦** | 需自签名 + 排除项指引；根治需正规代码签名证书 |

## 九、验收标准

> Given-When-Then 简表。全部可在校园网环境实测。

| 编号 | Given | When | Then |
|---|---|---|---|
| A1 | 已配置账号密码、已连校园网 | 点击「立即认证」 | 显示认证成功，外网可访问；配置中记录新 Token |
| A2 | 开机且已开启自启 | 系统启动 | 约 8 秒后自动认证，无需人工点击 |
| A3 | 已认证在线 | 手动断开网线再接回 | 守护线程在退避周期内自动恢复联网 |
| A4 | 手机与电脑连**同一热点** | 在电脑点「立即认证」 | 判定为「共享模式」提示，**手机不掉线** |
| A5 | 手机在线占名额 | 在电脑点「抢占上线」 | 手机被下线、电脑认证成功、界面提示接管 |
| A6 | 手机在线占名额 | 守护线程自动重连（`takeover=False`） | 电脑认证失败并提示，不主动踢手机（不产生互踢循环） |
| A7 | Token 已失效 | 触发任意认证 | 自动用账号密码换新 Token 并重试成功，日志出现「★ 已用账号密码换取新 Token」 |
| A8 | 未配置账号密码且 Token 失效 | 触发认证 | 明确提示「请配置账号密码或用扫码登录」，**不静默失败** |
| A9 | 窗口宽度 300 / 400 / 600 / 800 / 1000 / 1400 | 观察操作按钮区 | 任意宽度下按钮**零重叠**，换行正常 |
| A10 | 设置面板内容超出窗口高度 | 打开设置面板 | 可滚动滚动到底，「登录并保存」按钮可见可点 |
| A11 | 关闭主窗口时输入了未保存内容 | 点击关闭 | 弹窗确认，避免误丢配置 |
| A12 | Token 已配置 | 点击「检查 Token」 | 返回 Token 是否被服务端接受的明确结论 |
| A13 | 账号有多台在线设备 | 点击「在线设备」 | 弹出列表，标注设备类型与「（本机）」，可单台下线 |
| A14 | 旧版本 `config.json`（exe 同目录或 `C:\GaoGaoNetAUTO\`） | 首次运行改造后的版本 | 自动迁移到 `%LOCALAPPDATA%\GaoGaoNetAUTO\`，Token 可正常读出且已重加密为 DPAPI |
| A15 | onedir zip 解压后 | 双击 exe | 正常启动，配置写在 `%LOCALAPPDATA%\GaoGaoNetAUTO\`，exe 目录**无任何写入** |
| A16 | 未签名/自签名 exe | Defender 扫描 | `MpCmdRun` 返回 0；界面提供「更多信息→仍要运行」指引 |
| A17 | 配置目录不可写 | 启动程序 | 明确报错而非静默失败 |
| A18 | `pystray` 未安装 | 启动程序 | 正常显示主窗口，日志提示已跳过托盘 |
