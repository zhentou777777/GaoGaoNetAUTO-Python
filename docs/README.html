⚡ 三十秒速览

  1. 下载 Releases 里的 GaoGaoNetAUTO.exe，双击运行
  2. 先连上校园网（状态卡上能看到出口 IP）
  3. 点「扫码登录」→ 用手机糕糕 APP 扫一下 → 立刻联网

想让以后彻底不掏手机：设置区「① 账号密码」填云高手机号和密码 → 点「登录并保存」→ 勾选「开机自动认证」。

一、它是怎么做到"免手机"的

云高认证是一个 REST 接口，服务端只认请求头里的 Authorization: Bearer <Token>。

原生扫码流程（手机必须在场）：

PC 生成 code  →  手机扫码并用 Token 授权 code  →  云高标记 code 已授权  →  PC 绑定 IP 上线

但接口层其实有两个等价入口：

接口 语义 需要的凭据
GET /api/network/auth?str=<code> 授权「刚刚被手机同意的那次会话」 Token + 一个已被手机授权的 code
GET /api/network/auth?ip=<IP> 直接把指定 IP 挂进账号的在线设备 只要 Token

code 只是网页流程里传递"这次授权给哪台设备"的一次性载体。 走 auth?ip= 就把 code 整环跳过了——Token 替代了手机。 手机因此退化成一次性"Token 搬运工"，此后每次上线 PC 自己带 Token 调接口即可。

手机导出 Token(一次)  →  PC 本地加密保存  →  PC 调 auth?ip=  →  云高放行
                                          ↑______ 断网/开机时自动重放，手机不再参与

二、账号"只能登录一台设备"怎么办

云高账号同时只能有 1 台设备在线，所以：

  • PC 认证会顶掉手机，手机上的校园网会掉线（这是单名额的必然结果，不是 bug）。
  • 手机在 APP 里重新认证，又会把 PC 顶掉，并可能导致 Token 轮换。

程序对此做了三件事：

  1. 四级认证链，逐级回退，覆盖服务端"踢旧设备"和"拒绝新设备"两种行为：

`` auth?ip=<PC_IP> 直接认证 ↓ 失败 logout?ip=<PC_IP> → auth?ip= 清理本机陈旧会话后重试 ↓ 仍失败（判定名额被占） logout?ip=<手机IP> → auth?ip= 自动顶替手机（需在设置里填一次手机 IP） ↓ 仍失败 明确报错：区分「Token 已失效」与「账号被其他设备占用」 ``

  1. 「归还名额」按钮：一键把在线名额还给手机（logout?ip=<PC_IP>）。
  2. 只做 PC 独占，不实现热点/ICS/路由器共享。手机需要上网时用「归还名额」，

或自己在糕糕 APP 里下线 PC。

另：单名额下，MAC 地址一变就被当成新设备，更容易撞上限制。

建议对校园 Wi-Fi 关闭 Windows 的「随机硬件地址」

（设置 → 网络和 Internet → Wi-Fi → 属性 → 随机硬件地址 → 关闭）。

程序本身按"保持随机"设计，每次运行都会重新探测当前 IP/MAC，绝不硬编码。

三、Token 失效了怎么办（三层自愈）

Token 可能因为「在 APP 内退出账号」或「发生设备登录」而失效/轮换。 程序不会让你卡在抓包上：

层 机制 你的成本
L0 账号密码自动换 Token（推荐）：设置里填一次手机号+密码，Token 失效时程序自己去云高换一个 0，完全免抓包
L1 认证响应里若下发新 Token，程序自动解析并存下来（服务端轮换 Token 时无缝续命） 0
L2 Token 失效时自动降级到二维码模式，这条路径完全不依赖 Token 手机扫一下
L3 重新抓包 走一次抓包流程

L0：账号密码直接换 Token（彻底免抓包）

实测逆向了云高统一用户中心的登录接口：

POST https://user.v4.yungao-tech.com/api/login
Content-Type: application/json

{"mobile": "<手机号>", "password": "<密码>"}

错误码语义（实测）：

返回 含义
400 参数不能为空 字段名不对
408 手机号不合法 手机号格式错
401 账号不存在 该手机号在云高没注册
401 密码错误 账号存在但密码不对

注意：云高账号体系里，手机号就是登录名。

如果你的校园网账号不是手机号（比如学号），这条路径可能返回「账号不存在」，

这时仍走抓包或扫码。

在程序设置区填入手机号和密码 → 点「登录并保存」→ 账号与 Token 都会加密落盘。 之后 Token 失效时，程序会自动换一个新的继续认证——这才是真正的「自愈」。

密码与 Token 用同一套加密方案（机器指纹派生密钥 + HMAC 校验），

配置文件里是密文，换机器解不开。

另外面板会显示 Token 健康状态，提前预警，而不是等你断网才发现。

想用数据说话？可以跑一次实测脚本：

python tokenlab.py

它会：Token 认证一次 → 让你在手机上做一次设备登录 → 再用同一 Token 认证 → 直接给出「你这学校到底轮不换 Token」的结论。

想先验证账号密码能不能登录（不会保存任何东西）：

python login_check.py <手机号> <密码>

四、快速开始

开机自动联网 + 断网自动重连（你要的核心功能）

按这三步配置，之后就不用管了：

  1. 设置区填账号密码 → 点「登录并保存」

（或填手机号后点「扫码登录」扫一次，把 Token 存下来）

  1. 勾选 「开机自动认证」 → 点「保存设置」
  2. 完事

之后的行为：

场景 程序做什么
开机 注册表 Run 项静默启动 → 等 8 秒网络就绪 → 自动认证上线
断网 / 换网络 守护线程（20 秒一轮）发现断网 → 指数退避持续重试（15s → 30s → 60s → 120s 封顶）
出口 IP 变化 校园网重新分配 IP 会导致旧授权失效 → 检测到立即重新认证
Token 被服务端轮换 自动用账号密码换新 Token → 重新认证 → 存回本地
认证成功但外网不通 实测连通性，不通就如实提示并继续重试（校园网 DNS 未生效的常见坑）

为什么"扫码登录"撑不过一晚上？

扫码只是让服务端把当前这一台设备放行一次，

会话是有有效期的，网络断了或会话过期就得重来。

要真正"开机就连、断网自愈"，必须有能自己续期的 Token——

这就是账号密码登录（L0）存在的意义。

五、扫码登录是怎么做到"不依赖 Token"的

这条兜底路径完全独立于 Token，实测逆向了云高网页的实现细节：

  1. GET /web/network/code 会 301 到自身并下发 Set-Cookie: str=<UUID>，

这个 UUID 就是本次授权会话的标识，10 分钟有效。

  1. 页面把二维码内容用 XOR 混淆 内嵌在 JS 里：

``js var encoded = [253,172,255, ...]; var key = 158; var str = encoded.map(function (c) { return String.fromCharCode(c ^ key); }).join(''); qrcode.makeCode(str); ``

解码结果与 str cookie 完全一致（UUID 形式）。 所以本项目能纯本地渲染二维码，不必去扒服务端图片—— key 每个会话随机生成，本地解码器按同一算法还原即可。

  1. 手机 APP 扫完码后的最后一步是（手机抓包实测确认）：

`` GET hgs.auth.yungao-tech.com:1110/api/network/auth?str=<UUID> Authorization: Bearer <APP 自己的 Token> → 200 {"code":200,"msg":"认证成功。"} (36 字节) ``

也就是说，手机扫的是 PC 侧会话的 UUID，APP 用自己的 Token 替这次会话完成绑定。

> 重要：每次请求 /web/network/code 服务端都会下发新的 str， > 所以"UUID 变了"不能用来判断二维码过期——真正的判据是 10 分钟有效期。 > 本项目已按此实现，避免无限误判过期。

  1. 页面里没有任何状态轮询接口。手机确认后服务端直接改写

「该 session 对应的 IP」的上线状态。 因此判定"授权是否完成"的正确信号不是某个轮询接口，而是 本机是否已经能连通外网（netguard.probe_online）。

这套机制下，扫码路径的完整闭环是：

PC 拉页面 → 拿 str(UUID) → 本地渲染二维码 → 手机 APP 扫 → APP 调 auth?str=UUID → 服务端放行本机 IP → PC 检测到已联网 → 完成

程序还会在轮询时顺带调用 auth?str=<UUID> 做一次确认（若有 Token）， 两者任一成立即判定授权成功。

六、获取 Token（安卓 SSL 抓包）

云高网页登录流程本身不带 Authorization 头，所以从浏览器 DevTools 复制这条路多半取不到。

Token 只存在于糕糕 APP 的网络流量里。

  1. 安卓手机安装 抓包精灵 或 HttpCanary（任选其一）。
  2. 打开抓包工具 → 允许安装 CA 证书：
  3. 抓包精灵：设置 → 证书安装 → 安装到「系统证书」（部分机型需在系统设置里手动信任）；
  4. HttpCanary：设置 → 证书 → 安装。
  5. 开始抓包 → 打开 糕糕 APP，等几秒让它产生网络请求。
  6. 在抓包列表里按域名筛选。云高 APP 会访问这几个域名，带 Authorization 头的都在里面：
域名 说明
hgs.auth.yungao-tech.com 学校网关，最优先看这个（程序用的就是它）
user.v4.yungao-tech.com 云高统一用户中心，/api/user 族需要 Token
h5pay.yungao-tech.com 支付相关，一般用不上

> 若抓包工具显示「内容已隐藏」，把该域名加入解密域名列表即可查看。 > 想找现成的 Token，优先看 hgs.auth.yungao-tech.com/api/network/auth 这条—— > 它的请求头就是标准格式的 Authorization: Bearer ...。

  1. 点开请求 → 请求头 / Request Headers → 找到 Authorization：

`` Authorization: Bearer eyJhbGciOi... ^^^^^^^^^^^^^^^^^ 从这里开始复制，到行尾为止 ``

  1. 粘贴到主程序左下角的 Token 输入框 → 点「校验并保存」。

如果 HttpCanary 提示证书固定（Certificate pinning）导致看不到明文，

说明该 APP 启用了 SSL Pinning，普通抓包无法解密。

这时可以：① 换用「抓包精灵」等带 SSL Unpinning 的工具；

② 放弃 Token，直接用「扫码登录」模式（完全不需要 Token）。

注意：不要在糕糕 APP 里退出账号，退出后 Token 会立即失效。

八、常见问题

Q：提示"Token 已失效"？ 先看日志里的过程信息。若是账号名额被占，在设置里填上「手机 IP」； 若是 Token 真的轮换了，重新抓一次即可（期间可以用「扫码登录」顶一下）。

Q：提示"名额被占用"？ 你的账号同时只能有一台设备在线。把手机 IP 填进设置，程序会自动顶替； 或者先在 APP 里下线手机。

Q：能不能手机和电脑同时上网？ 云高单设备限制下服务端只允许一台。理论上可以让 PC 做 NAT 共享给手机， 但本项目按「PC 独占」设计，没有实现共享功能。

Q：抓包打不开 / 看不到明文？ 多半是 APP 启用了 SSL Pinning，用「扫码登录」模式即可绕过， Token 只是让你少掏手机，不是必需品。

Q：抓取模式 capture.py 是干嘛的？ 用于分析网页扫码流程中"手机确认之后 PC 靠哪个调用完成上线"， 以便把零 Token 的扫码助手彻底做实。需要额外装 Playwright：

pip install playwright
python -m playwright install chromium
python capture.py
