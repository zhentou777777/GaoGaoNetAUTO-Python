## 一、它是怎么做到"免手机"的

云高认证是一个 REST 接口，服务端只认请求头里的 **`Authorization: Bearer <Token>`**。

原生扫码流程（手机必须在场）：

```
PC 生成 code  →  手机扫码并用 Token 授权 code  →  云高标记 code 已授权  →  PC 绑定 IP 上线
```

但接口层其实有**两个等价入口**：

| 接口 | 语义 | 需要的凭据 |
|---|---|---|
| `GET /api/network/auth?str=<code>` | 授权「刚刚被手机同意的那次会话」 | Token + 一个已被手机授权的 code |
| `GET /api/network/auth?ip=<IP>` | **直接把指定 IP 挂进账号的在线设备** | **只要 Token** |

`code` 只是网页流程里传递"这次授权给哪台设备"的一次性载体。
走 `auth?ip=` 就把 code 整环跳过了——**Token 替代了手机**。
手机因此退化成一次性"Token 搬运工"，此后每次上线 PC 自己带 Token 调接口即可。

```
手机导出 Token(一次)  →  PC 本地加密保存  →  PC 调 auth?ip=  →  云高放行
                                          ↑______ 断网/开机时自动重放，手机不再参与
```

## 二、账号"只能登录一台设备"怎么办

云高账号同时只能有 1 台设备在线，所以：

- **PC 认证可能顶掉手机**，手机上的校园网会掉线（这是单名额的必然结果，不是 bug）。
- 手机在 APP 里重新认证，又会把 PC 顶掉，**并可能导致 Token 轮换**。

程序对此做了三件事：

1. **四级认证链**，逐级回退，覆盖服务端"踢旧设备"和"拒绝新设备"两种行为：

   ```
   auth?ip=<PC_IP>                        直接认证
     ↓ 失败
   logout?ip=<PC_IP> → auth?ip=           清理本机陈旧会话后重试
     ↓ 仍失败（判定名额被占）
   logout?ip=<手机IP> → auth?ip=          顶替手机（**需在设置里填一次手机 IP 并勾选开关**）
     ↓ 仍失败
   明确报错：区分「Token 已失效」与「账号被其他设备占用」
   ```

2. **「归还名额」按钮**：一键把在线名额还给手机（`logout?ip=<PC_IP>`）。
3. **默认不挤手机**：抢占是破坏性操作，所以程序**默认关掉**它。
   - 「立即认证」按钮走的是**非抢占**路径，不会踢掉占用名额的设备；
   - 要抢占必须显式点「抢占上线」，程序会**列出将被下线的设备 IP 并要求二次确认**；
   - 设置里的「名额被占时自动顶替手机」默认也是**关闭**的。

> 单名额下，MAC 地址一变就被当成新设备，更容易撞上限制。
> 建议对校园 Wi-Fi 关闭 Windows 的「随机硬件地址」
> （设置 → 网络和 Internet → Wi-Fi → 属性 → 随机硬件地址 → 关闭）。
> 程序本身按"保持随机"设计，每次运行都会重新探测当前 IP/MAC，绝不硬编码。

> **关于「手机和电脑同时上网」**：云高单设备限制下服务端只允许一台。
> 但如果电脑连的是**手机热点**，出口 IP 是同一个 —— 手机认证后电脑其实**已经能上网**，
> 此时程序会查服务端的在线列表确认「本机出口 IP 已在线」，**直接判定成功、不再重复认证**，
> 这样就不会把手机挤掉。

## 三、Token 失效了怎么办（三层自愈）

Token 可能因为「在 APP 内退出账号」或「发生设备登录」而失效/轮换。
程序不会让你卡在抓包上：

| 层 | 机制 | 你的成本 |
|---|---|---|
| **L0** | **账号密码自动换 Token**（推荐）：设置里填一次手机号+密码，Token 失效时程序自己去云高换一个 | **0，完全免抓包** |
| **L1** | 认证响应里若下发新 Token，程序**自动解析并存下来**（服务端轮换 Token 时无缝续命）；当前 Token 判定失效时还会**回退试一次上一版 Token** | 0 |
| **L2** | Token 失效**且没有账号密码**时，程序会**主动弹出二维码弹层**，这条路径完全不依赖 Token | 手机扫一下 |
| **L3** | 重新抓包 | 走一次抓包流程 |

### L0：账号密码直接换 Token（彻底免抓包）

实测逆向了云高统一用户中心的登录接口：

```
POST https://user.v4.yungao-tech.com/api/login
Content-Type: application/json

{"mobile": "<手机号>", "password": "<密码>"}
```

错误码语义（实测）：

| 返回 | 含义 |
|---|---|
| `400 参数不能为空` | 字段名不对 |
| `408 手机号不合法` | 手机号格式错 |
| `401 账号不存在` | 该手机号在云高没注册 |
| `401 密码错误` | 账号存在但密码不对 |

> **注意**：云高账号体系里，手机号就是登录名。
> 如果你的校园网账号不是手机号（比如学号），这条路径可能返回「账号不存在」，
> 这时仍走抓包或扫码。

在程序设置区填入手机号和密码 → 点「登录并保存」→ 账号与 Token 都会加密落盘。
之后 Token 失效时，程序会**自动换一个新的**继续认证——这才是真正的「自愈」。

> 密码与 Token 用同一套加密方案（**Windows DPAPI**，系统级、用户绑定、随机 nonce），
> 配置文件里只有密文，换机器或换用户都解不开。

另外面板会显示 **Token 健康状态**，提前预警，而不是等你断网才发现。

想用数据说话？可以跑一次实测脚本：

```bash
python tokenlab.py
```

它会：Token 认证一次 → 让你在手机上做一次设备登录 → 再用同一 Token 认证 →
直接给出「你这学校到底轮不换 Token」的结论。

想先验证账号密码能不能登录（不会保存任何东西）：

```bash
python login_check.py
# 交互式输入手机号与密码（密码不回显、不进 shell 历史）
```

> 也可以 `python login_check.py <手机号>` —— 手机号走命令行，**密码仍走交互输入**。
> 不建议把密码也写进命令行：那样同机的其他账号通过进程列表就能看到。

|---|---|
| **开机** | 在「启动」文件夹放一个快捷方式静默启动 → 等网络就绪 → 自动认证上线 |

## 五、扫码登录是怎么做到"不依赖 Token"的

这条兜底路径完全独立于 Token，实测逆向了云高网页的实现细节：

1. `GET /web/network/code` 会 **301 到自身**并下发 `Set-Cookie: str=<UUID>`，
   这个 UUID 就是本次授权会话的标识，10 分钟有效。
2. 页面把二维码内容用 **XOR 混淆** 内嵌在 JS 里：

   ```js
   var encoded = [253,172,255, ...];
   var key    = 158;
   var str = encoded.map(function (c) {
       return String.fromCharCode(c ^ key);
   }).join('');
   qrcode.makeCode(str);
   ```

   解码结果与 `str` cookie **完全一致**（UUID 形式）。
   所以本项目能**纯本地渲染二维码**，不必去扒服务端图片——
   `key` 每个会话随机生成，本地解码器按同一算法还原即可。
3. **手机 APP 扫完码后的最后一步是**（手机抓包实测确认）：

   ```
   GET hgs.auth.yungao-tech.com:1110/api/network/auth?str=<UUID>
   Authorization: Bearer <APP 自己的 Token>
   → 200 {"code":200,"msg":"认证成功。"}    (36 字节)
   ```

   也就是说，手机扫的是 **PC 侧会话的 UUID**，APP 用自己的 Token 替这次会话完成绑定。

   > **重要**：每次请求 `/web/network/code` 服务端都会下发**新的** `str`，
   > 所以"UUID 变了"不能用来判断二维码过期——真正的判据是 10 分钟有效期。
   > 本项目已按此实现，避免无限误判过期。

4. 页面里**没有任何状态轮询接口**。手机确认后服务端直接改写
   「该 session 对应的 IP」的上线状态。
   因此判定"授权是否完成"的正确信号不是某个轮询接口，而是
   **本机是否已经能连通外网**（`netguard.probe_online`）。

这套机制下，扫码路径的完整闭环是：

```
PC 拉页面 → 拿 str(UUID) → 本地渲染二维码 → 手机 APP 扫 → APP 调 auth?str=UUID → 服务端放行本机 IP → PC 检测到已联网 → 完成
```

程序还会在轮询时顺带调用 `auth?str=<UUID>` 做一次确认（若有 Token），
两者任一成立即判定授权成功。

## 六、获取 Token（安卓 SSL 抓包）

> 云高网页登录流程本身**不带** `Authorization` 头，所以**从浏览器 DevTools 复制这条路多半取不到**。
> Token 只存在于糕糕 APP 的网络流量里。

1. 安卓手机安装 **抓包精灵** 或 **HttpCanary**（任选其一）。
2. 打开抓包工具 → 允许安装 CA 证书：
   - 抓包精灵：设置 → 证书安装 → 安装到「系统证书」（部分机型需在系统设置里手动信任）；
   - HttpCanary：设置 → 证书 → 安装。
3. 开始抓包 → 打开 **糕糕 APP**，等几秒让它产生网络请求。
4. 在抓包列表里按域名筛选。云高 APP 会访问这几个域名，**带 `Authorization` 头的都在里面**：

   | 域名 | 说明 |
   |---|---|
   | `hgs.auth.yungao-tech.com` | **学校网关**，最优先看这个（程序用的就是它） |
   | `user.v4.yungao-tech.com` | 云高统一用户中心，`/api/user` 族需要 Token |
   | `h5pay.yungao-tech.com` | 支付相关，一般用不上 |

   > 若抓包工具显示「内容已隐藏」，把该域名加入**解密域名**列表即可查看。
   > 想找现成的 Token，优先看 `hgs.auth.yungao-tech.com/api/network/auth` 这条——
   > 它的请求头就是标准格式的 `Authorization: Bearer ...`。
5. 点开请求 → **请求头 / Request Headers** → 找到 `Authorization`：
   ```
   Authorization: Bearer eyJhbGciOi...
                       ^^^^^^^^^^^^^^^^^ 从这里开始复制，到行尾为止
   ```
6. 粘贴到主程序左下角的 Token 输入框 → 点「校验并保存」。

> 如果 HttpCanary 提示证书固定（Certificate pinning）导致看不到明文，
> 说明该 APP 启用了 SSL Pinning，普通抓包无法解密。
> 这时可以：① 换用「抓包精灵」等带 SSL Unpinning 的工具；
> ② 放弃 Token，直接用「扫码登录」模式（**完全不需要 Token**）。

**注意：不要在糕糕 APP 里退出账号**，退出后 Token 会立即失效。

## 七、界面说明

界面是**浏览器里的本地网页**（不是传统桌面窗口），跑在 `127.0.0.1` 的
本地服务上，URL 带一次性令牌。

| 区域 | 说明 |
|---|---|
| 状态卡 | 圆环进度显示当前状态（灰=未认证 / 黄=认证中 / 绿=在线 / 红=失败），中间是出口 IP，下方是网关 / MAC / 名额 / 设备四格信息 |
| 立即认证 | 执行四级认证链 |
| 扫码登录 | 弹出二维码弹层，手机扫一下即可（不依赖 Token） |
| 归还名额 | 把账号的在线名额还给手机 |
| 检查 Token | 只读体检（调 `onestatus` 接口），**不会改变在线状态**，不会占掉你的名额 |
| 设置 · Token | 粘贴 / 校验 / 保存 Token（DPAPI 加密存储，不落明文） |
| 设置 · 手机 IP | 单设备限制下用于自动顶替手机，填一次即可 |
| 设置 · 认证网关 | 不同学校的主机端口不同，默认 `hgs.auth.yungao-tech.com:1110`（**有白名单校验**，防止误填把 Token 发到别处） |
| 设置 · 开机自动认证 | 在「启动」文件夹放快捷方式实现开机自启 |
| 设置 · 清除已保存凭据 | 一键抹掉本机保存的 Token / 手机号 / 密码（含备份文件） |
| 运行日志 | 所有认证尝试、失败原因、降级过程都记录在这里（实时推送），同时落盘到 `logs/app.log`（自动脱敏 + 轮转） |

> 想要传统的桌面窗口？加 `--tk` 参数启动会切到旧版 Tk 界面
> （功能一样，只是没那么好看）。

配置文件在 `%LOCALAPPDATA%\GaoGaoNetAUTO\config.json`，**与 exe 放在哪里无关**，
目录权限已收紧到「当前用户 + SYSTEM + Administrators」。
Token 与密码用 **Windows DPAPI** 加密，换机器或换用户都解不开。
可在「设置 · 清除已保存凭据」一键清空。

## 八、常见问题

**Q：提示"Token 已失效"？**
先看日志里的过程信息。若是账号名额被占，在设置里填上「手机 IP」；
若是 Token 真的轮换了，重新抓一次即可（期间可以用「扫码登录」顶一下）。

**Q：提示"名额被占用"？**
你的账号同时只能有一台设备在线。把手机 IP 填进设置，程序会自动顶替；
或者先在 APP 里下线手机。

**Q：能不能手机和电脑同时上网？**
云高单设备限制下服务端只允许一台。但**如果电脑连的是手机热点**，两者共用同一个出口 IP ——
手机认证后电脑就直接能上网了，程序会识别这种情况并**跳过重复认证**（也就不会挤掉手机）。
除此之外本项目不做 NAT/ICS/路由器共享。

**Q：抓包打不开 / 看不到明文？**
多半是 APP 启用了 SSL Pinning，用「扫码登录」模式即可绕过，
Token 只是让你少掏手机，不是必需品。

**Q：抓取模式 capture.py 是干嘛的？**
用于分析网页扫码流程中"手机确认之后 PC 靠哪个调用完成上线"，
以便把零 Token 的扫码助手彻底做实。需要额外装 Playwright：

```bash
pip install playwright
python -m playwright install chromium
python capture.py
```
